# Timeline study edition — 2026-10-08

## Scope and content

91 entries in 10 eras, in English and Brazilian Portuguese. All 16 existing
`fixture.timeline.*` identities remain; 75 new identities use `editorial.timeline.*`.
Original bilingual prose provides an episode summary and its narrative connection,
with one or more chapter links. People and places link to existing graph pages;
this module does not duplicate their biographies or the Themes catalogue.

The catalogue is an initial study path, not an exhaustive history of the Bible.
This edition follows narrative/contextual order, not an asserted absolute calendar.
The exile group explicitly identifies contextual readings; the Jesus group notes
that episode order varies across the Gospels. Unverified years from demonstration
fixtures were replaced with null/unknown rather than republished as sourced history.
The original dated response is retained in `pipeline/sources/timeline/legacy.json`
for comparison. Some former broad fixture periods are now focused entry points
into the corresponding era; their stable IDs and existing entity links remain.

Source: `pipeline/sources/timeline/events.psv`. Builder:

```sh
cd pipeline
.venv/bin/python -m verbum_pipeline.timeline \
  --inventory /tmp/verbum-audio-inventory \
  --legacy sources/timeline/legacy.json
```

The local canonical inventory validates book/chapter existence. Editorial prose
was checked against the cited episodes by Codex under Lucas's explicit delegation;
this does not claim independent human or theological review. No copyrighted Bible
translation text is reproduced in this catalogue. Hash-bound review decisions are
stored in `pipeline/review/timeline-2026-10-08.json`.

## Architecture and growth

- One bilingual catalogue is published atomically by the existing pipeline; both
  mobile platforms read the same API content. No mobile era registry needs updating.
- Bundle v5 adds timeline discovery and explicit references to existing graph IDs.
  Publication validates those IDs and never rewrites the corresponding entities.
  Existing v1–v4 serialization/review hashes remain unchanged.
- Migration 0010 adds optional `timeline_events.discovery` JSONB. The existing
  endpoint and legacy fields remain available; old responses without metadata
  still render in the mobile clients. Localized discovery takes precedence over
  older translations. API event order is editorial position for enriched entries.
- Era overview → bounded era list → inline study and direct Scripture reading.
  Global search bypasses era browsing. Previous/next era navigation supports
  sequential study; deep links from people/places select the appropriate era.
- The API's existing entityNames response supplies chip labels, eliminating the
  per-entity network requests in production. Legacy/test clients retain a fallback.
- Event/period identity is explicit. A disputed date window is no longer drawn as
  an event duration merely because two years were supplied.

Further expansion should fill coverage gaps by era, with reviewed passages and
sources, keeping one stable identity per episode. Add a subperiod level when an era
outgrows a practical browsing list. At larger catalogue sizes, move search and era
pagination to the backend; the current 91-entry payload does not need speculative
infrastructure. Historical dating should be a separately sourced editorial layer,
with alternatives distinguished from duration. Do not infer dates from array order.
