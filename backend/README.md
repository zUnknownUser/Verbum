# backend/ — the Verbum API (Go)

Serves [`api/openapi.yaml`](../api/openapi.yaml). Standard library only; no framework, no
external dependency yet. Today it answers from the fixture file the apps ship
(`db/seed/fixtures.json`); the next step is the Postgres store.

## Run it

```sh
cd backend
go run ./cmd/api                 # http://localhost:8080
curl localhost:8080/v1/entities/fixture.person.david
curl "localhost:8080/v1/daily-verse?days=3"
go test ./...                    # contract tests: responses must equal api/examples/*.json
```

Docker (from the repo root): `docker build -f backend/Dockerfile -t verbum-api . && docker run -p 8080:8080 verbum-api`.

## How it is laid out

```
cmd/api/main.go            wires config → store → HTTP; graceful shutdown. Start reading here.
internal/domain/           the wire types — one struct per schema in openapi.yaml. No logic.
internal/store/store.go    the Store interface: the ONLY way handlers reach content. Read-only.
internal/store/memory/     Store over fixtures.json. Reference implementation; tests use it.
internal/httpapi/          server.go (routes) · handlers.go (one func per route) · problem.go (errors)
                           contract_test.go proves every api/examples/*.json is answered byte-for-byte.
internal/dailyverse/       the verse-of-the-day pick — same algorithm as the apps (tested on the same dates).
db/migrations/             Postgres schema (§25/§26/§33), idempotent SQL.
db/seed/fixtures.json      GENERATED by api/scripts/gen-examples.py — do not edit by hand.
```

Rules the code follows (from docs/PRODUCT.md):
- **Never invent.** No content for a chapter → `404 content_unavailable`, not a generated paragraph (§3.5).
- **Every claim is sourced** (§33): relationships, details and datings carry `sourceReferenceIds`.
- **One error shape** (§52): `Problem {code, message}`; handlers map `store.ErrNotFound` → 404,
  everything else → 500 with the detail logged, never sent.
- **Read-only.** Content enters through the editorial pipeline (`pipeline/`, §32), not this API.

## Next steps, in order (Task 11 in docs/ROADMAP.md)

1. **Postgres store** — `internal/store/postgres/` implementing `store.Store` with
   [pgx](https://github.com/jackc/pgx) (+ [sqlc](https://sqlc.dev) if you want typed queries from
   SQL files). The schema is in `db/migrations/0001_schema.sql`; `docker compose up -d` gives you a
   local database with it applied. Write a small `cmd/seed` that loads `db/seed/fixtures.json` into
   it. Then in `main.go`, select the store by `VERBUM_DATABASE_URL`.
   **Definition of done:** `go test ./...` passes with a `postgres`-backed variant of
   `contract_test.go` (same examples, same answers).
2. **Deploy** — the Dockerfile builds a distroless image; any container host works
   (Fly, Cloud Run, Railway, a VPS with Docker). Put a TLS terminator in front. Set `VERBUM_ADDR`.
3. **Apps go live** — `.live` clients on iOS and Android against this URL, with contract tests on
   the same `api/examples/` (see `api/README.md`).
4. **Search beyond names** — free-text passage search and semantic search (§27–28) extend
   `/v1/search` without changing its shape; pgvector when the pipeline produces embeddings.
5. **Observability** — replace the one-line request log in `server.go` with OpenTelemetry (§54).

Things that are deliberately *not* here: Scripture text (the apps read bible.helloao.org),
authentication (Phase 7 adds `/v1/me/...`), and any write endpoint.
